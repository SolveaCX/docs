Flatkey gibt dir einen Schlüssel und vier Wege, ihn einzusetzen. Alle vier teilen sich denselben Account, dasselbe Guthaben und denselben Modellkatalog — die einzige Frage ist, welcher zu deiner Arbeitsweise passt.

<Frame>
  ![Die vier Wege, Flatkey zu nutzen, dargestellt in der Flatkey Console](/images/quickstart/console-choose-how.png)
</Frame>

<Tip>
  Du musst dich nicht ein für alle Mal entscheiden. Beginne mit dem, was deiner aktuellen Arbeit am nächsten kommt, und ergänze die anderen später mit demselben Schlüssel.
</Tip>

## Bevor du startest

Erstelle einen Schlüssel unter [console.flatkey.ai/keys](https://console.flatkey.ai/keys). Flatkey-Schlüssel beginnen mit `sk-`. Jede der folgenden Optionen verwendet diesen einen Schlüssel — bewahre ihn also in einer Umgebungsvariable auf und halte ihn aus der Versionskontrolle heraus.

Jedes Panel in der Console erlaubt dir außerdem, statt einen neuen Schlüssel zu erstellen, einen vorhandenen auszuwählen, der dann direkt in das angezeigte Snippet eingesetzt wird.

## API für Entwickler

Rufe jedes Modell über einfaches HTTP mit einer OpenAI-kompatiblen Anfrage auf. Kein SDK, keine Abhängigkeiten — wenn du einen HTTP-Client hast, kannst du direkt loslegen.

<Frame>
  ![Das Panel „API für Entwickler“ mit einer sofort ausführbaren Anfrage](/images/quickstart/modal-api.png)
</Frame>

Die Console erstellt die Anfrage für dich: wähle einen Schlüssel, wähle ein Modell und kopiere das Snippet in **cURL**, **Node.js** oder **Python**.

```bash
curl https://router.flatkey.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FLATKEY_API_KEY" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"Say hello in one sentence."}]}'
```

## SDKs für Entwickler

Behalte das OpenAI SDK, das du bereits verwendest, und richte es auf Flatkey aus. Dein Anfrage-Code ändert sich nicht — nur die Basis-URL.

<Frame>
  ![Das Panel „SDKs für Entwickler“ mit dem SDK-Setup](/images/quickstart/modal-sdk.png)
</Frame>

Gleiches Prinzip wie oben: wähle einen Schlüssel und ein Modell, dann kopiere das Setup für deine Sprache.

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["FLATKEY_API_KEY"],
    base_url="https://router.flatkey.ai/v1",
)
```

## Flatkey CLI

Erzeuge Bilder und Videos direkt aus deinem Terminal, oder lass einen KI-Assistenten die CLI für dich steuern.

<Frame>
  ![Das Panel „Flatkey CLI“ mit Installation, Anmeldung und erstem Prompt](/images/quickstart/modal-cli.png)
</Frame>

<Steps>
  <Step title="Installieren">
    ```bash
    npm i -g @flatkey-ai/cli
    ```
  </Step>
  <Step title="Anmelden">
    ```bash
    flatkey login
    ```
  </Step>
  <Step title="Loslegen">
    Sag deinem KI-Assistenten, was du möchtest, und lass ihn die CLI ausführen:

    ```text
    Use Flatkey CLI to generate a "beautiful sunrise" picture.
    ```
  </Step>
</Steps>

<Card title="Flatkey CLI mit KI-Agent" icon="terminal" href="/de/guides/flatkey-cli">

</Card>

## Codex & Claude Code

Verbinde deinen Coding-Agenten einmal und nutze Flatkey anschließend aus den Projekten, die du bereits geöffnet hast.

<Frame>
  ![Das Panel „Codex und Claude Code“ mit dem Installationsbefehl](/images/quickstart/modal-agents.png)
</Frame>

Die Console gibt dir einen einzigen Installationsbefehl für **macOS**, **Linux** oder **Windows**. Er installiert den Agenten, falls du ihn noch nicht hast, fragt nach deinem Schlüssel und schreibt die Konfiguration für dich.

<Warning>
  Der Installer ist interaktiv. Er fragt, ob du Claude Code oder Codex CLI möchtest, und benötigt bereits installiertes Node.js.
</Warning>

## Überprüfe, ob es funktioniert hat

Egal, für welche Option du dich entschieden hast — öffne nach deiner ersten Anfrage **Usage Logs** in der [Console](https://console.flatkey.ai). Du solltest sie dort mit Modell, Token-Anzahl, Latenz und Kosten aufgelistet sehen.

![Verwende den Filter „Model Name“ in den Flatkey Usage Logs](/images/quickstart/flatkey-usage-logs.png)

Falls nichts erscheint, warte ein paar Sekunden und suche erneut, und überprüfe dann den API-Schlüssel und die Basis-URL, die die Anfrage tatsächlich verwendet hat.
