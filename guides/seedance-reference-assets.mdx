Base URL: `https://router.flatkey.ai`

Use the asset library when you want to upload a reference once and reuse it in `seedance-2.0` video requests. Replace `YOUR_FLATKEY_API_KEY`, `ast_1234567890abcdef1234567890abcdef`, and `rph_1234567890abcdef` with your own values.

You only send a Flatkey API key:

```http
Authorization: Bearer YOUR_FLATKEY_API_KEY
```

`asset://ast_...` is the Flatkey public URI that customers use in Seedance requests. BytePlus documents the upstream form as `asset://<Asset_Id>`; do not send that upstream ID to Flatkey. Flatkey rewrites `asset://ast_...` before calling BytePlus.

## Virtual asset library

Virtual assets are ordinary reference images, videos, or audio files, such as product shots, background clips, and non-person reference media. They do not require real-person verification.

### 1. Create from a public HTTPS URL

Virtual assets currently accept JSON with a public `https://` URL only. They do not support local `multipart/form-data` upload.

<CodeGroup>
```bash Bash
curl -sS https://router.flatkey.ai/v1/assets \
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://cdn.example.com/reference/product.png",
    "asset_type": "Image",
    "moderation": {
      "strategy": "Default"
    }
  }'
```
```powershell Windows PowerShell
curl.exe -sS https://router.flatkey.ai/v1/assets `
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" `
  -H "Content-Type: application/json" `
  -d '{
    "url": "https://cdn.example.com/reference/product.png",
    "asset_type": "Image",
    "moderation": {
      "strategy": "Default"
    }
  }'
```
</CodeGroup>

The response includes an `id` such as `ast_1234567890abcdef1234567890abcdef` and a status such as `Processing`. Virtual asset responses currently do not return `asset_uri`; build it yourself by adding `asset://` before the `id`.

```text
asset://ast_1234567890abcdef1234567890abcdef
```

### 2. Poll until Active

<CodeGroup>
```bash Bash
curl -sS https://router.flatkey.ai/v1/assets/ast_1234567890abcdef1234567890abcdef \
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY"
```
```powershell Windows PowerShell

  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY"
```

Only `Active` assets can be used in video generation. `Creating`, `Processing`, and `Deleting` are not ready. After deletion completes, `GET /v1/assets/{asset_id}` returns `404 asset_not_found`; do not wait for a pollable `Deleted` status.

### 3. Use the asset in Seedance

Put the `asset://ast_...` URI in the media field that matches the asset type: `image_url.url` for `Image`, `video_url.url` for `Video`, or `audio_url.url` for `Audio`. A Seedance request needs text or at least one image/video; audio alone is not enough.

<CodeGroup>
```bash Bash
curl -sS https://router.flatkey.ai/v1/videos \
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "seedance-2.0",
    "content": [
      {
        "type": "image_url",
        "image_url": {
          "url": "asset://ast_1234567890abcdef1234567890abcdef"
        },
        "role": "reference_image"
      },
      {
        "type": "text",
        "text": "Create a clean studio product video while keeping the product consistent"
      }
    ],
    "resolution": "1080p",
    "ratio": "16:9",
    "duration": 5
  }'
```
```powershell Windows PowerShell
curl.exe -sS https://router.flatkey.ai/v1/videos `
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" `
  -H "Content-Type: application/json" `
  -d '{
    "model": "seedance-2.0",
    "content": [
      {
        "type": "image_url",
        "image_url": {
          "url": "asset://ast_1234567890abcdef1234567890abcdef"
        },
        "role": "reference_image"
      },
      {
        "type": "text",
        "text": "Create a clean studio product video while keeping the product consistent"
      }
    ],
    "resolution": "1080p",
    "ratio": "16:9",
    "duration": 5
  }'
```
</CodeGroup>

Copy the returned `task_...` value. Use the public result step below for every Seedance task, whether it uses virtual assets or real-person assets.

### 4. Get and save the finished video

Use this endpoint to poll the task:

```http
GET /v1/videos/{task_id}
```

Poll until `status` is `completed`, then copy the download URL from `metadata.url`. If the status is `failed`, read `error.message`, fix the request or source asset, and create a new task. The Bash example uses `jq` to read JSON fields.

<CodeGroup>
```bash Bash
TASK_ID="task_3f9a00000000000000000000000000e2"

while true; do
  RESULT=$(curl -sS "https://router.flatkey.ai/v1/videos/$TASK_ID" \
    -H "Authorization: Bearer YOUR_FLATKEY_API_KEY")
  STATUS=$(echo "$RESULT" | jq -r '.status')
  echo "status: $STATUS"

  [ "$STATUS" = "completed" ] && break
  if [ "$STATUS" = "failed" ]; then
    echo "$RESULT" | jq -r '.error.message'
    exit 1
  fi
  sleep 5
done

VIDEO_URL=$(echo "$RESULT" | jq -r '.metadata.url')
curl -L "$VIDEO_URL" -o output.mp4
```
```powershell Windows PowerShell
$taskId = "task_3f9a00000000000000000000000000e2"

while ($true) {
  $result = curl.exe -sS "https://router.flatkey.ai/v1/videos/$taskId" `
    -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" | ConvertFrom-Json
  Write-Host "status: $($result.status)"

  if ($result.status -eq "completed") { break }
  if ($result.status -eq "failed") { throw $result.error.message }
  Start-Sleep -Seconds 5
}

$videoUrl = $result.metadata.url
Invoke-WebRequest -Uri $videoUrl -OutFile output.mp4
```
</CodeGroup>

`metadata.url` points to `GET /v1/videos/{task_id}/content`. It streams `video/mp4` after the task completes. Treat the URL as sensitive because anyone with it can download the video.

### 5. Delete the asset

<CodeGroup>
```bash Bash
curl -sS -X DELETE https://router.flatkey.ai/v1/assets/ast_1234567890abcdef1234567890abcdef \
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" \
  -i
```
```powershell Windows PowerShell
curl.exe -sS -X DELETE https://router.flatkey.ai/v1/assets/ast_1234567890abcdef1234567890abcdef `
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" `
  -i
```
</CodeGroup>

A successful delete returns an empty `204`. Repeating the same delete also returns `204`. A missing or non-owned asset returns `404 asset_not_found`.

## Real-person asset library

Real-person assets are for a specific person's face, voice, or video. This capability is limited access. Use it only after Flatkey enables it for your account.

The person must complete BytePlus verification before you create usable real-person assets. Keep the `verification_url` private and send it only to that person.

Real-person endpoints:

| Endpoint | Use |
| --- | --- |
| `POST /v1/real-persons` | Create a profile and verification link. |
| `POST /v1/real-persons/{person_id}/verification-sessions` | Create a new verification link. |
| `GET /v1/real-persons/{person_id}` | Poll profile status. |
| `POST /v1/real-persons/{person_id}/assets` | Create an asset from a public URL or local file. |
| `GET /v1/real-persons/{person_id}/assets` | List assets under one profile. |

Three backend asset ingestion paths:

| Path | What you send | What Flatkey does |
| --- | --- | --- |
| Public HTTPS URL ingestion | JSON with `url` and `asset_type` | The server passes the public HTTPS URL to BytePlus asset creation. |
| Local multipart ingestion | `multipart/form-data` with one `file` | The server stores the file in private temporary object storage before handing it to BytePlus. |
| TOS-first, GCS fallback | The same multipart request | When complete TOS support is available, the backend uses TOS first; otherwise it uses the existing private GCS fallback. This is backend availability dependent. |

You do not choose the storage provider. The customer-facing request format stays the same, and responses do not return a temporary URL, bucket, or BytePlus credentials.

### 1. Create a real-person profile

Real-person write requests require `Idempotency-Key`. Reuse the same key only when retrying the exact same request.

<CodeGroup>
```bash Bash
curl -sS https://router.flatkey.ai/v1/real-persons \
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" \
  -H "Idempotency-Key: person-create-20260802-001" \
  -H "Content-Type: application/json" \
  -d '{"name":"Ava Chen"}'
```
```powershell Windows PowerShell
curl.exe -sS https://router.flatkey.ai/v1/real-persons `
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" `
  -H "Idempotency-Key: person-create-20260802-001" `
  -H "Content-Type: application/json" `
  -d '{"name":"Ava Chen"}'
```
</CodeGroup>

The response includes a profile `id`, a `status`, and a one-time `verification_url`. The profile can be `pending_verification`, `verifying`, `active`, `failed`, or `expired`.

Send `verification_url` to the real person. They must open it and finish verification. `GET /v1/real-persons` and `GET /v1/real-persons/{person_id}` do not return that URL again.

If the link expires or verification fails, create a new verification session:

<CodeGroup>
```bash Bash
curl -sS -X POST https://router.flatkey.ai/v1/real-persons/rph_1234567890abcdef/verification-sessions \
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" \
  -H "Idempotency-Key: person-reverify-20260802-001"
```
```powershell Windows PowerShell
curl.exe -sS -X POST https://router.flatkey.ai/v1/real-persons/rph_1234567890abcdef/verification-sessions `
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" `
  -H "Idempotency-Key: person-reverify-20260802-001"
```
</CodeGroup>

BytePlus callback method is not guaranteed by the upstream docs. Flatkey accepts both GET and POST callback requests and treats them only as a wake-up signal. The server still checks the authoritative verification state with BytePlus.

### 4. Create a real-person asset from a local file

Local upload uses `multipart/form-data` and is available only for real-person assets. You do not choose TOS or GCS and you do not receive storage paths. Flatkey temporarily stores the file privately, passes it to BytePlus for asset creation, and cleans the temporary object after BytePlus stores the asset.

BytePlus official limits are expressed in MB. Flatkey local validation currently uses binary limits: Image `< 30 MiB`, Video `<= 50 MiB`, and Audio `<= 15 MiB`. For the safest result, keep files below the official MB limits.

<CodeGroup>
```bash Bash
curl -sS https://router.flatkey.ai/v1/real-persons/rph_1234567890abcdef/assets \
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" \
  -H "Idempotency-Key: real-person-asset-file-20260802-001" \
  -F "asset_type=Image" \
  -F "name=portrait" \
  -F "file=@./portrait.png"
```
```powershell Windows PowerShell
curl.exe -sS https://router.flatkey.ai/v1/real-persons/rph_1234567890abcdef/assets `
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" `
  -H "Idempotency-Key: real-person-asset-file-20260802-001" `
  -F "asset_type=Image" `
  -F "name=portrait" `
  -F "file=@.\portrait.png"
```
</CodeGroup>

The response includes `asset_uri`, for example `asset://ast_1234567890abcdef1234567890abcdef`.

### 6. Delete, privacy, and common errors

Delete real-person assets with the same endpoint as virtual assets:

<CodeGroup>
```bash Bash
curl -sS -X DELETE https://router.flatkey.ai/v1/assets/ast_1234567890abcdef1234567890abcdef \
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" \
  -i
```
```powershell Windows PowerShell
curl.exe -sS -X DELETE https://router.flatkey.ai/v1/assets/ast_1234567890abcdef1234567890abcdef `
  -H "Authorization: Bearer YOUR_FLATKEY_API_KEY" `
  -i
```
</CodeGroup>

Do not log or publicly expose `verification_url`, personal media, BytePlus credentials, TOS/GCS paths, or temporary transfer URLs.

Common responses:

| HTTP | Code | What to do |
| ---: | --- | --- |
| 400 | `invalid_asset_request` | Fix JSON, URL, `asset_type`, multipart fields, or asset/media mismatch. |
| 403 | `access_denied` | Make sure the API key can use `seedance-2.0` and the real-person feature. |
| 404 | `asset_not_found` | The asset is missing, deleted, or not owned by this API key. |
| 409 | `asset_not_ready` | Poll again after the asset finishes processing. |
| 409 | `real_person_not_active` | Wait until the profile is `active`. |
| 409 | `idempotency_conflict` | Use a new `Idempotency-Key` for a different request. |
| 413 | `asset_file_too_large` | Compress the local file below the supported limit. |
| 415 | `asset_media_unsupported` | Use supported image, video, or audio formats. |
| 422 | `asset_failed` | Create a new asset from a corrected source file. |

Need every Seedance option? See the [Seedance API Reference](/api-reference/seedance-video-generation).
